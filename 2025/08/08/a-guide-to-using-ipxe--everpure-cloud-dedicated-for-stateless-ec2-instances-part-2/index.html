A Guide to Using iPXE + Everpure Cloud Dedicated for Stateless EC2 Instances - Part 2

August 8, 2025 · 6 min read · 1226 words
Share

Welcome back to Part 2 of the Using iPXE + Everpure Cloud Dedicated for Stateless EC2. In the first part of the series we covered getting all the details ready, Part 2 will dive deeper into the AWS and Everpure ecosystem to get an EC2 instance deployed running on an iSCSI SAN booted volume.

Prerequisites#

  • Python
  • GitHub Reposistory for AWS Third Party Storage
  • Deployed Cloud Block Store on AWS
  • (Optional) Install Terraform

Recap#

Previously we covered the basics of kicking off the process to get a stateless EC2. It included the following steps:

  1. Prerequisite Setup
  2. Building and Exporting the boot image
  3. Downloading boot image to our local machine

In Part 2 we will cover the remaining items which include:

  1. Create and mount an EC Dedicated volume to jump host
  2. Write boot image to be used as a template
  3. Deploy Stateless EC2 with boot volumes on EC Dedicated.

Now that we have all this out of the way, lets begin!

Prepare jump host and Write Boot Image#

In order to write our image, we first need to mount a volume to our jump host. My linux machine is running as an EC2 instance in the same VPC so this will be quite easy.

This process will include two steps.

  1. Create a Host and Volume on Pure EC Dedicated Array
  2. Configure Linux iSCSI to connect and mount the volume

If iSCSI and multipath have not yet been installed on your jump host it can be installed via the local package management

yum -y install iscsi-initiator-utils device-mapper-multipath

Check if a valid IQN has been assigned, if not create one and restart the iSCSI Service

Next, we will need to create the host object on our Everpure Cloud Dedicated. You can use the UI or CLI for this task, for simplicity we will do these tasks via the CLI.

To begin, SSH to the management VIP of your EC Dedicated Appliance. Using the following command you will create the host object using the IQN that was gathered above.

purehost create --iqnlist iqn.1994-05.com.amazon:i-02bf0d3e31cefdcf5 jumphost1

We will need to give the volume a name and size, when the image was converted in Part 1–the size of the image should be listed in the S3 path you uploaded the image to.

Create the volume using the size parameter from above.

purevol create --size 10G jumphost1-data

Connect the volume to the host object using the following command.

purehost connect --vol jumphost1-data jumphost1

Now that the jump host is prepped and the volumes mapped we can proceed to configure iSCSI on our jump host. The following script can be used to configure iSCSI and map it inside the guest OS.

#!/bin/bash

# Set the IP addresses and initiator name here.
ISCSI_TARGET_IP1="172.18.10.68"
ISCSI_TARGET_IP2="172.18.10.92"

# Discover and log in to iSCSI targets
iscsiadm -m discovery -t st -p ${ISCSI_TARGET_IP1}:3260
iscsiadm -m node -p ${ISCSI_TARGET_IP2} --login
iscsiadm -m node -p ${ISCSI_TARGET_IP1} --login

Gather the path to the volume, as we are using multipath we can list the volumes using the following command.

sudo multipath -ll

Since the volume size was 10GB, lets look for this in the output. In this case it is mpathf

Now that we have the volume connected to our jump host, use dd to write the RAW image we had downloaded previously.

sudo dd if=<pathtoraw> of=/dev/mapper/<diskpath> bs=8M status=progress oflag=sync

Once the image has been successfully written to our volume, we will un map and disconnect our volume. We will also copy to a new volume as a gold image and then take a snapshot in case we need to ever revert back to its original state.

purehost disconnect --vol jumphost1-data jumphost1
purevol copy jumphost1-data ubuntu24-goldtemplate
purevol snap --suffix v1 ubuntu24-goldtemplate

We are now ready to create a new EC2 using our Ubuntu image!

Create your Stateless EC2 Instance#

Let’s get ready to deploy our first EC2. This can be accomplished via the AWS Console or Terraform and includes 2 simple steps.

  1. Everpure - Create the Host object, clone the template volume and map it to the host object.
  2. AWS - Deploy an iPXE Based AMI and use the user data to configure iPXE boot to our image

Create Everpure Resources#

Create the host object, volume and connect them. Make sure to connect the volume as lun1 (lun0 is reserved and cannot be used)

purehost create ubuntu1 --iqnlist iqn.2010-04.org.ipxe:ubuntu1
purevol copy ubuntu24-goldtemplate ubuntu1-boot
purehost connect --lun 1 --vol ubuntu1-boot ubuntu1

In order to iSCSI sanboot we need to gather 2 items from the EC Dedicated array. The first is the array IQN, the second are the iSCSI interface IPs.

pureport list
purenetwork eth list

Using the outputs from above, let’s construct a user data file we will use to bootstrap our EC2.

#!ipxe

# --- iPXE Variables ---
set initiator-iqn iqn.2010-04.org.ipxe:ubuntu1
set target-ip1 172.18.10.68
set target-ip2 172.18.10.92
set array-iqn iqn.2010-06.com.purestorage:flasharray.22a52e281e6dbb52

# --- iPXE Boot Commands ---
dhcp
sanboot iscsi:${target-ip1}:::1:${array-iqn} iscsi:${target-ip2}:::1:${array-iqn}

We are now ready to deploy our EC2 Instance.

Create EC2 Instance#

We will cover the deployment of the EC2 instance two ways, one using the AWS Console and one with Terraform. In order to deploy the instance, we need to use the iPXE AMI. You can use the following site to find the iPXE AMI id to use.

Amazon Web Services Console#

Since I am using us-west-2 as a region I will use the following AMI to launch an EC2 instance. You will need to provide a name, an instance type, Key pair and network configuration. Make sure to select an appropriate VPC, Subnet and Security Group that allows access to your EC Dedicated array.

NOTE:
You can leave the default EBS size as 1 GiB as this drive will not be used.

Do not forget to navigate to the advanced section and make sure to add your user data script.

When your parameters are complete, you can now launch your instance. If needed, you can use console to code and get a CLI command to use in the future. To check the progress of your instance booting, navigate to Actions -> Monitor and troubleshoot -> Get instance screenshot.

If everything was configured appropriately you should see a successful boot of your EC2 instance.

You can now ssh into your instance using the key pair you provided during the deployment.

Conclusion#

Building and deploying a stateless EC2 is not that difficult once you have the prerequisites out of the way. Following a simple set of steps gives you a streamlined process, when using automation it makes it even easier and repeatable!
